# Glossary

| Term | Definition |
|------|------------|
| TreeNote | The application name (working title). |
| User | A registered person who owns one or more workspaces. |
| Workspace | A container that holds one or more concept maps. |
| Concept Map | A visual representation of related topics arranged hierarchically or as a graph. |
| Topic | The primary content element visible to users. Represents an idea, concept, or note. |
| Node | The technical implementation of a Topic in the backend and database. |
| Root Topic | A Topic without a parent. A workspace may contain multiple root topics. |
| Child Topic | A Topic connected below another Topic. |
| Parent Topic | A Topic that has one or more child topics. |
| Relationship | A connection between two Topics. |
| Tree | A hierarchy where each Topic has at most one parent. |
| Graph | A structure where a Topic may have multiple parents. |
| Multi-parent Relationship | A Topic connected to more than one parent. This is an optional feature. |
| Canvas | The interactive drawing area where concept maps are displayed. |
| Workspace Settings | Configuration specific to a workspace. |
| Drag & Drop | Moving Topics using the mouse or touch. |
| Expand | Display child Topics. |
| Collapse | Hide child Topics. |
| Zoom | Increase or decrease the canvas scale. |
| Pan | Move the visible area of the canvas. |
| Export | Generate external files such as PDF or PNG. |
| Offline Mode | Ability to continue using the application without an internet connection. |
| Sync | Upload locally stored changes once connectivity is restored. |
| Product Backlog | Ordered list of all features planned for the project. |
| Sprint | A fixed development iteration with a defined goal. |
| Epic | A large feature composed of multiple user stories. |
| User Story | A requirement written from the user's perspective. |
| Task | A technical activity required to implement a user story. |
| Acceptance Criteria | Conditions that determine when a feature is complete. |
| Definition of Done (DoD) | Checklist that every completed feature must satisfy before it can be considered finished. |
